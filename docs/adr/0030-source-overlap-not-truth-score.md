# ADR 0030 — Source Overlap: what the byline percentage is, and what it is not

## Status
Accepted

## Context
The design system adopted in ticket 39 (`DESIGN-SYSTEM.md`, variant E) builds its `.byline` — which it calls "nosný prvek celého produktu" — around a percentage with a ten-segment gauge, labelled `shoda 62 %`. Nothing in this codebase produces such a number. The only `score` anywhere in the schema is `MatchDecision.score`, a cosine similarity used to decide whether two articles describe the same event, which is unrelated.

This matters more than a missing field usually would, because CLAUDE.md opens by saying the tool "is not meant to declare a winner, assign a truth score, or replace the reader's judgement," and ADR 0012 keeps the Cross-Source Narrative from adjudicating any disputed fact. A percentage attached to a whole story, shown on every listing row and every Article, is exactly the surface where that principle either holds or quietly stops holding.

The obvious implementation was to add the field to the Synthesis prompt: Synthesis already makes one structured-output call validated by a zod schema, so one more key costs nothing and needs no second call. That option was considered and rejected — see below.

## Decision

**The percentage is derived by counting, never generated by a model.** For each item in the `agreement` dimension, the backend counts the distinct outlets among its `attributions`; the metric is the mean of those counts over the Analysis's non-excluded source count. Two properties follow, and both are the point: it is reproducible — the same Synthesis result always yields the same number — and it is checkable by a reader, who can count the attributions on the page and arrive at the same figure.

Asking the model for the number instead would have broken both. Synthesis already runs a programmatic verification-and-repair loop over every `czechQuote`, checking it verbatim against the source text and re-prompting or discarding items that fail (ticket 17, ADR 0014). Every figure and quote a reader sees in this product today is machine-checkable against a source. A model-emitted percentage would be the first that is not, and the repair loop would have nothing to check it against.

**What the number measures is source overlap, not agreement about the world.** It answers "how much of the agreed-upon core of this story is carried by how many outlets." It does not measure whether the sources are right, whether a well-covered claim is more likely true, or whether an outlet is reliable. Two outlets reprinting the same wire copy produce high overlap and no independent confirmation whatsoever; the metric cannot tell those apart and does not try.

**It is labelled "překryv zdrojů", not "shoda".** This is a deliberate deviation from the reference design's own wording, and the only one made to its text. "Shoda" is read as *this is probably true*. "Překryv zdrojů" is read as *this is how much the sources share*, which is the only claim the arithmetic supports. A number that is honest and a label that oversells it would still be a truth score in a reader's hands.

**The model does contribute a judgement, and it is categorical.** Synthesis returns one story-level `agreementCategory` of `CONFIRMED` / `PARTIAL` / `DISPUTED` alongside the four dimensions. Counting cannot see two outlets stating the same fact in different words; the model can, and that reading is worth having. Expressing it as a float is not — this is the same trade-off ADR 0022 made for `StoryRelation.confidenceTier`, for the same reason: a `0.73` invites being read as a credibility measurement, an enum does not. The category drives the byline chip; the counted percentage drives the gauge. They come from different places and are not derived from each other.

**The gauge is withheld below five sources.** A ten-segment bar over three sources moves in thirds; the resolution the design implies is not in the data. Below the threshold the chip and the source count still show, so the byline never loses its meaning — it loses a decoration that would have implied precision it does not have.

## Consequences
- The metric can be recomputed for any Analysis at any time from data already stored, so a change to its definition is a code change, not a migration plus a re-run of paid LLM calls. Had it been model-generated, revising it would have meant re-running Synthesis across the archive.
- An Analysis whose `agreement` dimension is empty has no overlap to report. The stored percentage is nullable for that reason, and for every Analysis completed after this ticket shipped, null means "undefined for this story", never "not computed yet" — the column is filled on every completion going forward, so there is no pending state any new row can be in. That assumed an empty table at ship time; it wasn't one; see the migration's own comment (`20260820174624_add_source_overlap/migration.sql`), which backfills 4 pre-existing rows by their explicit ids. Those 4 rows' null `sourceOverlapPercentage` really does mean "never computed" — a closed, one-time set fixed at migration time, not a state any Analysis completed from here on can enter.
- The 85 / 65 interpretation thresholds from `DESIGN-SYSTEM.md` §3.3 live in the backend exactly once, next to the derivation. The frontend receives an interpreted result and never re-implements the boundaries — the failure mode this avoids is the UI and the API disagreeing about what "partial" means.
- Source overlap is not comparable across Analyses with very different source counts, and nothing in the product presents it as a ranking. There is no sorting, filtering or leaderboard by overlap, and adding one would re-introduce the winner-declaring this ADR exists to avoid.
- If independent-versus-syndicated coverage ever needs distinguishing, that is a new signal on `Coverage`, not a correction to this metric. This number will still be measuring what it says it measures.
